# 提效统计（productivity_fact + 仪表盘）

## 事实从哪来（`service/productivity_service.py`）

各来源的原始记录各自在自己的表里；这里把它们整理成同一种“事实”，按 `source_key` 幂等写入（重复整理不重复计数）。
整理时机：打开仪表盘时（最多每 5 分钟一次），以及每天一次（提醒规则 `productivity_refresh`）。

| 来源 | 草稿 | 采纳 | 原样采纳 | 正式业务 / 完成 |
|---|---|---|---|---|
| AI 材料整理（automation_work） | 整理成功 | 保存成业务草稿 | 没改字段 | 已保存 / 后续待办都办完 |
| 助手办理的业务（tool_confirmation） | 请求确认 | 员工确认执行 | 同左 | 确认执行 / 执行成功 |
| 发票识别（invoice_extraction） | 识别 | 员工确认 | 没改字段 | 用于报销 |
| CRM 下一步建议 | 生成建议 | 创建任务 | 没改直接创建 | 创建 / 待办办完 |
| IT 自助 | 推荐了文章 | 点了“已解决” | 同左 | 解决且没有重新打开 |
| Agent 运行（agent_run） | — | — | — | 只用来算失败率和失败原因 |

## 指标口径

- **节省时间** = 基准分钟 − Agent 用时 − 人工核对用时，最低为 0；只算被采纳 / 完成的。
  AI 整理用各工作流自己的基准（`baseline_minutes`），其他来源默认：发票 5、CRM 建议 3、IT 自助 20、助手办理 5 分钟，
  可用 `PRODUCTIVITY_BASELINES`（JSON，如 `{"invoice": 8}`）调整。
- **草稿采纳率** = 被确认的草稿 ÷ Agent 生成的草稿；**原样采纳率** = 没改字段直接确认的 ÷ 被确认的。
- **业务完成率** = 最终完成的 ÷ Agent 发起的正式业务；**失败率** = 失败的 AgentRun ÷ 全部 AgentRun。
- **三种时间分开展示，不相加**：估算节省（按基准）、实测用时（Agent 运行 + 人工核对的真实耗时）、
  员工反馈节省（员工在 AI 整理结果下面自己填的“这次大概省了多少分钟”，单独存，重新整理不会覆盖）。
- 人工修改字段分布：员工确认前改过的字段（AI 整理结果的字段、发票字段），改得多的优先改进。
- 失败原因：优先用运行时记下的统一错误码；早期没有错误码的按错误信息归类（超时、没配置模型、业务系统不可用……）。

## 页面

- 后台 → 提效统计（`/admin/productivity`）：全企业，平台管理员。
- 部门工作台 → 部门提效（`/department/productivity`）：本部门，只有部门负责人和企业管理员能看。

两者展示：总处理量、活跃用户、三种时间、四个比率、每日趋势、各部门 / 各助手 / 各类工作排行、失败原因、人工修改字段分布；可切换 7 / 30 / 90 天。

测试：`tests/test_productivity.py`。
