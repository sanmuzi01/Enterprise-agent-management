# 中央助手：统一入口、按问题转交部门助手

员工只需要找一个助手——**企业中央助手**。它不自己办业务，而是听懂问题、转交给合适的部门助手；
网页聊天和飞书 / 钉钉机器人都先经过它（飞书 / 钉钉接入时，有可用的中央助手就用中央助手）。

## 转交规则（service/runtime/central_router.py）

按部门助手模板里的关键词（`routing_keywords`）判断问题属于哪个部门，然后：

| 情况 | 结果（`reason`） | 例子（销售员工） |
|---|---|---|
| 员工在这个部门，部门有已发布的助手 | 转交该部门助手（`routed`） | “帮我跟进一下这个客户” → CRM 销售助手 |
| 员工不在这个部门，但这是**他自己的通用办公事务**（请假、考勤、报销、IT 工单） | 交给**员工本部门的助手**（`own_department`） | “帮我报销 300 元打车费”“我还有几天年假”“电脑连不上 VPN” → CRM 销售助手 |
| 员工不在这个部门，且是部门专属业务（采购、客户……） | 中央助手说明“你没有可用的助手”（`no_usable_agent`） | “查一下 A4 纸的库存” |
| 没命中任何部门 | 中央助手自己回答（`no_match`） | “你好，你能做什么” |

- 部门助手只对本部门成员开放（权限不变）；所以每个部门助手模板都带上了**通用办公工具**（请假、报销、IT 工单、
  入转调离任务、责任协同、考勤、读群聊），本部门员工自己的这些事在本部门助手里就能办。审批类工具仍由服务端按部门负责人权限把关。
- 通用办公事务由模板的 `general_keywords` 标出（人事：请假 / 年假 / 假期 / 休假 / 调休 / 考勤；财务：报销 / 发票 / 费用；IT：全部）。
- 一个问题命中多个部门：转给命中最多的那个，其余作为“备选”给员工明确切换；每次转交决定都记在 `agent_handoff`，
  管理后台能查。只在新会话时转交一次，同一会话后续消息不再转。

## 用哪个模型连接（service/llm/llm_config_service.py::use_agent_credentials）

企业助手（中央 / 部门）是企业提供给员工的，**员工不用自己配模型 Key**：员工自己没配这个模型时，运行期间依次找
助手创建人 → 企业所有者 / 管理员 → 平台管理员，用第一个配了这个模型的人的连接（Key 只在服务端使用，员工看不到；
员工自己配了同一个模型时仍用自己的）。个人助手不受影响。

**所以：由管理员（例如 `admin` 账号）在“模型连接”里配置一次部门助手用的模型（默认 glm-4），全公司的企业助手就都能用。**
只配在某个普通员工账号上不算企业连接——那个人以外的员工用企业助手时会提示“请先配置模型”。

## 搭建步骤

1. 管理员登录，在“模型连接”里配置部门助手使用的模型（默认 glm-4）。
2. “组织架构”里每个部门设置业务类型，“部门专业 Agent”发布部门助手（状态显示“需要修复”就点一键修复）。
3. “企业智能体”里用“企业中央助手”模板新建中央助手，发布。

验证：员工登录后找中央助手问“我还有几天年假”“帮我报销 300 元打车费”，回答上方会显示交给了哪个助手、为什么。

测试：`tests/test_central_router_plan.py`（含本部门兜底）、`tests/test_enterprise_credentials.py`（企业模型连接）。
